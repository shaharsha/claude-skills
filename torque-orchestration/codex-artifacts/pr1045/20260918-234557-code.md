### 1. Upgrade-path test does not pin DEFAULT 1

`tests/test_canary_backfill.py:9-10` · **low** · test-gap · confidence 0.98

**Evidence.** “The default is not the bug and these tests do not touch it.” Every seeded client also binds `is_real` explicitly in `_insert`, so the upgrade ALTER's default is never observed.

**Failure scenario.** Change only the upgrade migration to `ADD COLUMN ... DEFAULT 0`, leaving the fresh-database DDL at DEFAULT 1. These tests create a fresh table where the ALTER no-ops, then insert every row with explicit `is_real=1`, so they remain green. An existing deployment would acquire DEFAULT 0, and a later one-statement INSERT omitting `is_real` would silently create a simulated tenant.

**Suggested fix.** Add an older-shape upgrade test that drops `clients.is_real`, reruns `init_db()`, inserts a client without naming `is_real`, and asserts the stored value is 1.
