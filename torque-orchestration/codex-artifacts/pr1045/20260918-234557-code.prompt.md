## INTENT

### Goal

Two repairs to what PR #1040 shipped.

**TOR-1355.** #1040 added `clients.is_real` to distinguish a real client's data from fixture/canary
tenants, and shipped it as `ALTER TABLE clients ADD COLUMN IF NOT EXISTS is_real INTEGER NOT NULL
DEFAULT 1`. On an existing table a `NOT NULL DEFAULT` fills every pre-existing row with the default,
so the column arrived true of every row — including the canaries. Measured on the dev database
2026-09-18, read-only: `clients` holds 10 rows, all 10 with `is_real = 1`; three are canaries
(`browser_drill_co`, `silver_canary`, `tor682_canary`) and seven are real tenants (`loora`, `whalo`,
`vybs`, `tailor_brands`, `fortect`, `almedia`, `simply`). This commit adds the missing data half: a
backfill setting those three to 0.

**TOR-1354.** `_REAL_PRODUCTS`, a list literal in `api/routers/companies.py`, was deleted by #1040.
110 citations of it remained across 40 files. The commit rewrites the ones a reader would ACT on and
leaves the historical records verbatim.

### Requirements and invariants

1. The `DEFAULT 1` must NOT change. Adding a real tenant must stay a single INSERT; a default of 0
   makes every real client a two-step creation whose forgotten second step is silent.
2. The three canaries must be identified by an explicit named list, never by a pattern. A
   `slug LIKE '%canary%'`/`'%drill%'` predicate would demote a future real tenant whose slug contains
   the word and would miss a canary named otherwise.
3. The canary ROWS must not be deleted. They are kept pending a product decision.
4. `init_db()` runs the DDL and then every statement in `_PG_MIGRATIONS`, on EVERY container boot
   (`scripts/start.sh`). A migration must therefore be idempotent and must not lock or rewrite a
   served table on a no-op boot.
5. The backfill must not silently revert a later operator decision. `torque-admin tenant update
   <slug> --real` (`scripts/torque_admin.py`) writes this column, so a statement that re-asserts
   `is_real = 0` on every boot would undo that at the next deploy.
6. Schema changes are additive-only. A destructive `ALTER`/`DROP` needs human confirmation and is out
   of scope.
7. For TOR-1354: historical records — past tense, dated, or sha-anchored — are the record and must
   survive. Only text a reader would act on should change. A sweep-and-replace over the token would
   destroy the historical half.

### Runtime context

PostgreSQL only (the SQLite-shaped DDL is translated by `db/pg.py`; `_PG_MIGRATIONS` entries are raw
PostgreSQL and are not translated). The connection pool is autocommit. `init_db()` runs at container
start before gunicorn; if any statement raises, the deploy fails on both environments. dev and prod
already hold a `clients` table, so `CREATE TABLE IF NOT EXISTS clients` no-ops there and those
databases get columns only from the `ALTER`s — which is why `CHECK (is_real IN (0,1))` exists only on
a fresh database and `is_real = 2` is representable on dev and prod. Prod currently holds zero
`clients` rows; dev holds ten.

### Settled decisions (do not re-litigate; do challenge whether the code implements them)

* One-shot rather than re-asserted-every-boot, guarded by the existence of a `COMMENT ON COLUMN
  clients.is_real`, read from `pg_description`. This follows the `run_product_covenants` migration
  lower in the same tuple, which guards a `COMMENT ON COLUMN` the same way, and the ENG-7
  `auth_session_families` backfill above it, whose comment states the principle: after rollout the
  live row is authoritative and a later boot must never downgrade it from a stale source.
* The UPDATE and the COMMENT are in one `DO` block so a database cannot end up backfilled without its
  marker, or marked without its backfill.
* `is_real = 0` re-BADGES rather than hides. `api/services/client_registry.py` `_SELECT` filters on
  `product_code IS NOT NULL AND provisioning_state = 'active'` and never on `is_real`; the flag
  becomes the picker entry's `real` field, which the frontend renders as a "Simulated" badge. The set
  the canaries leave is `real_product_codes()`.

### Constraints hit while building

`tests/conftest.py` drops the public schema before every test and the `conn` fixture calls

Each test therefore rewinds by issuing `COMMENT ON COLUMN clients.is_real IS NULL`, which is the
pre-TOR-1355 shape — the same provision-then-rewind-then-boot technique as
`tests/test_init_db_against_existing.py`.
