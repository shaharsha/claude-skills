## Findings

### 1. An all-error sweep exits successfully as a zero-movement run

`scripts/measure/tor1297_sweep.py:171-178` · **medium** · error-handling · confidence 0.99

**Evidence.** The dead-probe guard is conditional on `graded`: `if graded and not any(...)`. When every builder was caught as an error, `graded` is empty, the guard is skipped, and execution reaches the normal summary and `return 0`.

**Failure scenario.** Run the hand measurement against a reachable database lacking every population slot's required tables. Each builder exception is caught into an `error` row, leaving `graded=[]`. The command exits 0 and prints `period set MOVED on 0`, allowing a completely unmeasured run to be treated as successful evidence.

**Suggested fix.** Exit nonzero when `graded` is empty before applying the existing all-zero dead-probe check.

### 2. Render-time bound failures cannot name the offending trace

`authored_pages/_recipe/as_of.py:1934-1935` · **medium** · spec-violation · confidence 0.98

**Evidence.** The resolver records only `{"latest": m["latest"], "grain": m["grain"]}` for each projected trace. Consequently, the renderer's refusal at lines 1717-1721 can only say "a marked trace reaches only ..." and cannot identify the trace, despite the stated requirement that it be named.

**Failure scenario.** A recorded all-projection verdict contains marked traces `collections` ending at the declared edge and `run-off` extending beyond it. `rendered_check_problem` correctly refuses the record, but its error cannot name `collections`, leaving the operator unable to identify which builder trace is mis-marked. Anonymous traces are even less identifiable.

**Suggested fix.** Record a diagnostic trace label, preferably figure/trace ordinal plus the name when present, in every `projected_traces` entry and include it in the renderer refusal. Do not use that label in the verdict predicate.

### 3. Sweep still treats period-set movement as settling verdict movement

`scripts/measure/tor1297_sweep.py:138-149` · **medium** · correctness · confidence 0.97

**Evidence.** The tool sets `row["moved"] = sorted(b) != sorted(c["periods"])` and marks a verdict undecided only when both sets are empty. It later prints that otherwise "the set comparison decides every row", although a changed non-empty period set does not determine whether the resolver verdict changed.

**Failure scenario.** With declared edge 2026-05, an unmarked actual trace reaches 2026-06 and a neutral-named projection reaches 2026-07. The old module counts both; the current module excludes the marked projection. The period sets differ, but both resolvers refuse because the actual trace still exceeds the edge. The sweep reports movement without flagging the verdict as unmeasured, under a tool described as auditing verdict movement.

**Suggested fix.** Either resolve the same as-of record through both modules and compare verdict/refusal outcomes, or describe and report only period-set movement and remove the claim that non-empty set comparison settles the verdict.
