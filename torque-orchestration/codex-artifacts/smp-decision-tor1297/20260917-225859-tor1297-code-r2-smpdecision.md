## Findings

### 1. Renderer accepts no-period records with missing exclusion counters

`authored_pages/_recipe/as_of.py:1637-1647` · **medium** · api-contract · confidence 0.97

**Evidence.** The check uses `(rc.get("periods_before_exclusion") or 0) > 0` and `(rc.get("excluded_traces") or 0) > 0`, so absent or negative counters are treated as non-evidence. The following check similarly treats an absent `periods_seen` as zero. This was established by source inspection; tests could not be executed in the read-only environment.

**Failure scenario.** Start with an all-projection record whose payload hash, product, slot, edge, and version markers are valid. Change its verdict to `no-period-axis`, remove `periods_before_exclusion` and `excluded_traces`, and change its sentence to the plain form. `rendered_check_problem` accepts the record, and build_page's remaining checks also accept it, even though the resolver would produce `all-projection` or refuse that same page. An immutable page with dated projection axes can therefore be rendered as if it had no dated axis.

**Suggested fix.** Require both counters to be present as non-negative integers on every verdict; require exactly zero for `no-period-axis`, and reject projection-span fields on that verdict.

### 2. Weakest-trace compression fails for day-grain edges

`authored_pages/_recipe/as_of.py:1872-1893` · **medium** · correctness · confidence 0.93

**Evidence.** The record chooses the weakest trace with `span = sorted(..., key=lambda m: _end_instant(...))` and stores `span[0]["latest"]`. The renderer later validates only that value. However, `_beyond_edge` lines 1534-1539 deliberately does not use end instants for a day-grain edge, so end-instant order is not equivalent to the resolver's per-trace predicate. This behavior is inferred from the source because tests could not run.

**Failure scenario.** With edge `2026-05-15` at day grain, one marked trace ending at month `2026-05` fails the resolver's bound, while another ending at day `2026-05-16` passes. End-instant sorting calls the day trace weakest because May 16 precedes May 31. A record describing these traces with `projected_weakest: 2026-05-16` is accepted by the renderer even though the resolver refuses the monthly trace. Current database resolution normally coarsens daily edges to months, so this is an edge case involving a hand-edited or legacy day-grain record.

**Suggested fix.** Record each marked trace's latest value and grain and have the renderer apply `_beyond_edge` to every entry; alternatively, explicitly refuse day-grain `all-projection` records at both doors.
