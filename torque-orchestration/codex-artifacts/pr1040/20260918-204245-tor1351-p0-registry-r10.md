## Findings

### 1. Workbook can combine registry and pointer data from different snapshots

`scripts/page_status_workbook.py:441-442` · **medium** · correctness · confidence 0.97

**Evidence.** `state = _pointer_state(conn)` and `tenants = client_registry.tenants(conn)` execute as separate statements on an autocommit connection.

**Failure scenario.** A tenant has product code `ACME` and published pointers. The workbook reads pointer state keyed by `ACME`; then `tenant update --slug acme --product-code ACME2` commits before the registry read. The registry returns `ACME2`, but `state` contains only `ACME`, so the generated workbook falsely reports the tenant's slots as having nothing published even though those pointers now serve through `ACME2`.

**Suggested fix.** Read pointer state and tenants inside one `conn.read_only_snapshot()` transaction, or fetch both through a single statement keyed by stable client ID.
