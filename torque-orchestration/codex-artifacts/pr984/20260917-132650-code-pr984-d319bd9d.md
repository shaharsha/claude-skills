## Findings

### 1. Zero-percent scenarios are displayed as funded labels

`api/services/lr/loan_simulator.py:538-540` · **high** · correctness · confidence 0.98

**Evidence.** The detail status falls through to the scenario label whenever the cohort is neither declined nor cap-blocked: `status = ("Declined" if i in declined else "Cap-limited" if i in blocked else (_lbl if _lbl is not None else "Funded"))`. The grid has the same fallthrough at lines 369-375. Static inference: `fund_pct` explicitly permits 0, while `compute_lr_loan_offer_b` skips a zero disbursement without adding the cohort to funded, blocked, or declined.

**Failure scenario.** An operator edits the applicable Offer-B scenario’s Fund % to 0, which is permitted by the editable grid. `_pick_offer_b_scenario` still returns that scenario, but the model’s `dis <= 0` branch deploys nothing and records the cohort in none of its outcome sets. Both status sites nevertheless show the authored scenario label, and Cohort Detail gives it the funded `ok` tone, even though no funding occurred.

**Suggested fix.** Gate scenario labels on membership in `funded_cohorts`. Render the agreed non-funded fallback (the legacy-compatible `—` is available) for a cohort in none of the three sets, and give it a non-funded/neutral tone. Add a zero-Fund-% arm to the agreement test.

### 2. Outcome-like scenario labels receive the wrong status tone

`api/services/lr/loan_simulator.py:566-573` · **medium** · correctness · confidence 0.97

**Evidence.** Tone is inferred from rendered text: `if val in ("Blocked", "Declined"): return "bad"` and `if val in ("Breach", "Cap-blocked", "Cap-limited"): return "warn"`. Scenario labels are unrestricted editable text, and the change now places them directly in this cell.

**Failure scenario.** A funded scenario is authored with the exact label `Declined` (or `Blocked`, `Breach`, or `Cap-limited`). The required label is rendered exactly, but the funded cohort is colored bad or warning because its label collides with an outcome word. This regression did not occur with the former dict representation.

**Suggested fix.** Determine the status tone from the cohort index’s funded/declined/blocked membership, not from the displayed label. Add a test using labels that collide with each reserved outcome word.

### 3. Agreement test ignores an active grid cohort rendered as a dash

`tests/api/test_lr_sim_offer_b_status_label.py:367-370` · **medium** · test-gap · confidence 0.96

**Evidence.** The grid collector explicitly drops every `—` row: `sites[f"control:{key}"] = {i: r["status"] for i, r in enumerate(val) if r["status"] != "—"}`. The later comparison only examines sites containing that cohort (`if i in words`) and never asserts equal cohort-key sets.

**Failure scenario.** A regression makes only active cohort C5 in the sigma grid render `—`, while Cohort Detail remains correct. The basic vocabulary test permits `—`; the mixed-label test checks only C0-C2; long-label and empty-label tests filter or tolerate the missing grid value; and the agreement test silently removes C5 from the grid before comparing. All tests can pass while one rendered status site is wrong.

**Suggested fix.** Before comparing meanings, assert that every site contains every modeled cohort (derive the expected indices from the captured model result), while allowing placeholder rows only beyond `n_cohorts`. Do not discard an active `—` before that coverage assertion.
