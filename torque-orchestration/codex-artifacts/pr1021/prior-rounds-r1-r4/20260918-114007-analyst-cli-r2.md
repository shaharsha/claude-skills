## Findings

### 1. Newer unverified runs bypass the non-sealed refusal

`api/services/vault/raw_read.py:158-188` · **high** · correctness · confidence 0.99

**Evidence.** `verified = [c for c in candidates if c["state"] == "verified" and c["version_id"]]` is applied before `newest` and `tied` are calculated, and the non-sealed check examines only `tied`.

**Failure scenario.** Run A is sealed with verified `revenue.csv`. A later run B records the same path but is still open, or sealing/failed with that object `expected`, `missing`, or `mismatch`. B is excluded from `verified`, so `newest` becomes A and resolve silently returns A's older bytes with no mention of B. This contradicts the new refusal's stated rule that silently falling back answers a question the analyst did not ask. The same omission occurs when A and B share a start timestamp.

**Suggested fix.** Determine the newest timestamp from all path-matching candidates first. Without `--run`, refuse if any candidate at that newest timestamp has a non-sealed session; only then select verified, VersionId-bearing rows. Add open and failed-mismatch fixtures newer than an older sealed run.

### 2. The advertised -o path cannot fetch oversized objects

`scripts/torque_admin.py:573-591` · **high** · api-contract · confidence 0.99

**Evidence.** The wrapper calls `raw_read.fetch(conn, args.slug, args.path, args.run, args.max_bytes)` before consulting `args.out`; therefore the service's default ceiling applies identically with and without `-o`.

**Failure scenario.** For a recorded object larger than `DEFAULT_MAX_BYTES`, `torque-admin raw fetch ... -o export.csv` exits with the size refusal. That refusal itself says `-o <path>` writes the whole object with no ceiling, so following its remedy produces the same error. `test_an_oversized_object_is_refused_rather_than_truncated` checks only that the message contains `-o`; it never invokes the CLI with an output file, so it remains green.

**Suggested fix.** Thread an explicit file-output mode into the service and bypass the terminal-oriented ceiling for that mode, preferably streaming the pinned response directly to the file. Add a CLI-level oversized `-o` test.

### 3. served_to_readers is false for versions readers can request

`api/services/control_plane/artifacts.py:1079-1084` · **high** · correctness · confidence 0.98

**Evidence.** `"served_to_readers": bool(chosen.get("is_live")) and chosen.get("serve_mode") == "manifest"` treats every non-live version, and every version on a legacy-pinned slot, as unserved.

**Failure scenario.** Publish HTML v1 and v2, leaving v2 live, then call `fetch_artifact(..., version=1)`. The result says `served_to_readers: false`, but `/api/products/ACME/slots/historical?v=1` deliberately resolves and serves v1. Likewise, a legacy-pinned live version is reachable via `?v=N`. `test_a_legacy_pinned_slot_reports_that_nobody_is_served` only asserts this derived flag and never exercises the explicit-version serve path, so it passes while naming a false behavior.

**Suggested fix.** Define the field narrowly as `served_by_default` using the current predicate, or represent both default serving and explicit-version reachability. Test the flag against `page_resolution.resolve_source(..., version=N)`.

### 4. Missing output selection is checked only after the S3 read

`scripts/torque_admin.py:573-606` · **medium** · error-handling · confidence 1

**Evidence.** `raw_read.fetch(...)` runs at line 579, while the `-o`/`--stdout` refusal is not checked until line 601. The resulting error nevertheless states `Nothing was read from the object`.

**Failure scenario.** Invoke `torque-admin raw fetch --slug acme --path revenue.csv` without either output option. The command performs the pinned S3 GET and reads up to the full default ceiling into memory, then exits claiming nothing was read. `test_raw_fetch_does_not_put_client_bytes_on_stdout_unasked` checks only captured stdout, so it cannot detect the S3 read and still passes.

**Suggested fix.** Validate the output-choice requirement before calling `raw_read.fetch`, ideally with a required mutually exclusive argparse group. Spy on fetch/S3 in the refusal test to prove no read occurred.

### 5. Mismatch errors invent a missing VersionId and unusable remedy

`api/services/vault/raw_read.py:158-167` · **medium** · error-handling · confidence 0.99

**Evidence.** When no candidate is object-level verified, the error always says the row has “no recorded VersionId” and instructs the operator to “seal the session”. Seal records a VersionId even for size/checksum mismatches, then marks the session failed; failed sessions cannot be sealed again.

**Failure scenario.** Seal a run whose `p.csv` exists but has the wrong size or checksum. Its row becomes `state='mismatch'` with a real VersionId and its session becomes `failed`. `raw fetch --run ... --path p.csv` says there is no VersionId and recommends `torque-admin run seal`, which fails because only open sessions may be sealed.

**Suggested fix.** Build the refusal from the actual object and session state. For mismatch rows, say that the recorded version failed verification; for failed sessions, direct the operator to create a replacement run rather than re-seal it.
