## Findings

### 1. Streaming accepts bytes beyond the sealed size

`api/services/vault/raw_read.py:391-406` · **medium** · correctness · confidence 0.99

**Evidence.** `limit = size + _CHUNK` followed by `if limit is not None and written > limit` permits up to a full extra chunk, despite the comment saying that “more bytes than the seal recorded” is a mismatch.

**Failure scenario.** A row records actual_bytes=10, but the pinned VersionId returns 11 bytes because the row is inconsistent with S3. With the default chunk size, all 11 bytes are renamed into place, bytes_read is 11, and truncated is false. The advertised size-integrity check never fires.

**Suggested fix.** For an unbounded file fetch, require `written == size` before `os.replace`; additionally stop before writing once `written + len(chunk) > size`. For ranged writes, compare against `min(size, max_bytes)`.

### 2. Open-session refusal recommends a seal that can destroy the run

`api/services/vault/raw_read.py:195-201` · **medium** · error-handling · confidence 0.98

**Evidence.** For every open candidate the message says: `Seal the open run(s) and the copy becomes readable`, without knowing whether the object has arrived or matches its declaration.

**Failure scenario.** Immediately after create_session, the object row is `expected`, the session is `open`, and no PUT has arrived. `raw fetch` instructs the analyst to seal; doing so marks the object missing and the session failed, after which it cannot be sealed again and a new drop is required.

**Suggested fix.** For open sessions, say to finish the upload and then seal, and state that readability depends on successful verification. Do not promise that sealing alone makes the copy readable.

### 3. The state-partition test does not inspect resolve

`tests/test_vault_raw_read.py:741-744` · **low** · test-gap · confidence 0.99

**Evidence.** The test hard-codes `ACCEPTED, REFUSED, UNREACHABLE = {"sealed"}, {"failed", "sealing"}, {"open"}` and only checks those constants against the discovered literals; it never derives the partition from or invokes `resolve`.

**Failure scenario.** Change `resolve` to admit a failed or sealing session. This test remains green because its asserted partition is independent of the implementation, despite its docstring claiming the states are “accounted for by resolve.” Other behavioral tests may catch current mutations, but this named closure assertion cannot fail for its stated reason.

**Suggested fix.** Parameterize behavioral resolve cases from the discovered state set, or narrow the test claim to enumeration only and rely explicitly on separately enumerated behavioral tests for the partition.

### 4. CLI usage still calls unserved legacy HTML served bytes

`scripts/torque_admin.py:32-34` · **low** · spec-violation · confidence 0.99

**Evidence.** The command synopsis describes artifact fetch as `the stored bytes a reader is SERVED`, while the implementation now deliberately returns `served_by_default: false` for a live version under `serve_mode='legacy'`.

**Failure scenario.** Fetch the default version of a legacy-pinned slot. The command returns the live HTML that ordinary requests bypass for the builder, but its usage documentation tells the operator these are the bytes a reader is served.

**Suggested fix.** Describe it as the stored HTML named by the live pointer, and direct readers to `served_by_default` to determine whether an unqualified request uses it.
