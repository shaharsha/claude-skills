# GPT on Azure / Microsoft Foundry and AWS Bedrock - host request contracts

Read this when a GPT model runs on Azure OpenAI / Microsoft Foundry or AWS Bedrock. **Read `gpt.md` first, in full**: it describes OpenAI's own API, and this file lists only what a host changes (endpoints, model names, reasoning replay, caching, structured output, rejected fields). Step 0b in SKILL.md sends you here.

## Contents
- Azure OpenAI / Microsoft Foundry
- AWS Bedrock

GPT runs on the OpenAI API, Azure / Microsoft Foundry, and AWS Bedrock (GPT-6 Astra launched on all three; 6.1 Terra went GA on Foundry on launch day via the Responses API; **GPT-6.2 Astra and Sol went GA on Foundry and Bedrock on Nov 17**, their launch day), with Google Cloud Model Garden announced (Oct 21 2026, GA "in the coming weeks"). Prompt engineering follows the **model version, not the platform**, but the request contract does not.

## Azure OpenAI / Microsoft Foundry

- **Endpoint & model name.** Call `https://YOUR-RESOURCE.openai.azure.com/openai/v1/` and pass your **deployment name** as `model`. Auth is API key or Microsoft Entra ID. New models may need a quota request.
- **Roles.** `developer` is equivalent to `system` on Azure reasoning models, and the latest models accept `system` too - but **don't send both in one request.**
- **Token limit parameter.** Reasoning models use **`max_completion_tokens`** (Chat Completions) / **`max_output_tokens`** (Responses); `max_tokens` is not supported. Always set `reasoning.effort` explicitly.
- **Unsupported sampling knobs.** `temperature`, `top_p`, `presence_penalty`, `frequency_penalty`, `logprobs`, `top_logprobs`, `logit_bias` are unsupported on reasoning models.
- **Reasoning summaries** via `reasoning.summary` (`auto` / `detailed`; GPT-5 series doesn't support `concise`). **Don't try to extract raw reasoning by other means** - it violates the Acceptable Use Policy.
- **GPT-6.2 on Foundry** (Microsoft's launch post, Nov 17 2026): Global Standard, Data Zone Standard (US, EU, APAC) and Global Provisioned deployments; Data Zone prices run 10% (US) or 20% (EU, APAC) above Global Standard; and both models take **12-hour cache writes** on Standard deployments (`prompt_cache_options.ttl:"12h"`).
- **Foundry-exposed features:** `preamble` objects, `allowed tools` under `tool_choice`, the `custom`/`lark_tool` grammar tools, and per-deployment **content filters** (configured in the portal, not the prompt).

## AWS Bedrock

Checked against the AWS model cards for GPT-6.1 Sol and GPT-6 Sol on Nov 7 2026 and for GPT-6.2 Astra and Sol on Nov 18; cards differ by model - GPT-6 Luna's lists different feature support - so check yours. **The 6.2 cards** list the same two endpoints and APIs as 6.1 Sol's (`us.openai.gpt-6.2-astra` / `global.openai.gpt-6.2-astra` on `bedrock-runtime`, `openai.gpt-6.2-astra` on `bedrock-mantle`; same pattern for Sol), explicit caching on Responses, Chat Completions and InvokeModel but not Converse, 30-minute cache writes only, no Priority or Flex tier, a 10% fee on In-Region and Geo inference, and Ultrafast on Astra only (on `bedrock-mantle` in `us-east-1` or through the `bedrock-runtime` profiles). Neither these cards nor Microsoft's launch post says whether the 6.2 prefix check and `instructions` change apply on the host, so check `input_transformations` and cached-token counts on your own deployment. The notes below were observed on 6.1 Sol:

- **Two endpoints, four APIs.** `bedrock-runtime` serves Responses, Chat Completions, Converse and InvokeModel, through cross-Region inference profiles only (`us.openai.gpt-6.1-sol`, `global.openai.gpt-6.1-sol`; the OpenAI-compatible base URL is `https://bedrock-runtime.{region}.amazonaws.com/openai/v1`). `bedrock-mantle` serves Responses and Chat Completions under `/openai/v1`, in-Region in `us-east-1` (`openai.gpt-6.1-sol`). Features differ between them: reasoning summaries are Responses-only on `bedrock-mantle`, and Guardrails exist only on `bedrock-runtime` (not with Responses).
- **Converse runs GPT tool loops, with its own reasoning contract.** GPT reasoning arrives as `reasoningContent.redactedContent` (opaque bytes): pass it back unchanged, read content blocks by type, never send `reasoningText` in an assistant turn (GPT rejects it, which bites when a router hands a Claude conversation to GPT), and don't send back an empty reasoning block (400). SDK issue reports (pi, inspect_ai, LangChain, Haystack, hermes-agent) agree on these.
- **Reasoning summaries on Converse** are set with `additionalModelRequestFields.reasoning.summary` (Converse's own error message lists `concise`, `detailed` and `auto` as the accepted values). With summaries on, Converse returned the summary as a `reasoningText` block with no signature and no `redactedContent`, and asking for `include:["reasoning.encrypted_content"]` didn't bring the encrypted reasoning back; sending that `reasoningText` back in an assistant turn was refused ("This model doesn't support the reasoningContent.reasoningText.text field for assistant messages"), and leaving it out means no reasoning carries to the next turn (one team's live Converse calls on `us.openai.gpt-6.1-sol` through `bedrock-runtime`, Nov 2026; no request ids kept, and AWS's card doesn't say). So in a tool loop, turn summaries off and replay `redactedContent`, or check that encrypted reasoning still round-trips before turning them on. At low effort on a trivial question no summary came back at all.
- **Caching differs by API and by model, and the card can lag the API.** AWS's GPT-6.1 Sol card says Converse has implicit caching only and doesn't support the native `cachePoint`. Live Converse calls on Nov 7 2026 (one team, `us.openai.gpt-6.1-sol`, no request ids kept) found otherwise: a `cachePoint` at the end of `system[]` was accepted and the next request read 3,457 of 4,273 input tokens from the cache (0 without one), and one inside a user message was accepted too; but in `toolConfig.tools` it was rejected (`ValidationException`: "This model doesn't support the cachePoint field"), and so was `ttl:"1h"` ("Extended TTL prompt caching is only supported for Anthropic models"). On Bedrock models without prompt caching, any `cachePoint` fails with a misleading `AccessDeniedException` (reported for GPT-5.6 models in SDK and sample-repo issues, and seen live on Grok 4.7). Explicit caching on Responses, Chat Completions or InvokeModel uses `prompt_cache_options` (`mode:"explicit"`, `ttl:"30m"`, the card's only TTL) with `prompt_cache_breakpoint`; the prefix minimum is 1,024 tokens, with up to four cache writes per request. Check `cacheReadInputTokens` on your own model and API before relying on either the card or this note.
- **Converse rejects sampling fields.** Open-source bug reports (Oct-Nov 2026) show Bedrock Converse returning "This model doesn't support the temperature field" (and the same for `topP`) for GPT-5.6 and GPT-6 models, 0 and 1 included (the reports don't say which effort was set). Send no sampling fields to GPT on Bedrock's Converse API.
- **Converse content and structured output.** GPT-6.1 Sol on Converse rejects `document` blocks and images inside a `toolResult` (`ValidationException`); send documents through Responses `input_file`. Strict JSON Schema on Converse needs `additionalModelRequestFields.text.format.strict: true` in addition to `outputConfig.textFormat`.
